# Рабочий формат API Талдау (найден 2026-07-09 через DevTools)

## Endpoint
POST https://taldau.stat.gov.kz/ru/NewIndex/GetIndexTreeData
Content-Type: application/x-www-form-urlencoded

## Параметры (Form Data) — пример для показателя "уровень занятости" (702841)
p_parent_id  = 741880              # корень (РК). Для районов СКО: 264023
p_index_id   = 702841              # id показателя
p_period_id  = 7                   # год
p_measure_id = 7
p_term_id    = 741880
p_terms      = 741880,741917,741935
p_dicIds     = 67,749,576          # РАЗРЕЗЫ — свои для каждого показателя!
idx          = 0
filter       = [{"property":null,"value":null}]
id           = 741880

## Ответ
JSON-массив регионов. Каждый: {"id":"264023","text":"СЕВЕРО-КАЗАХСТАНСКАЯ ОБЛАСТЬ","y122014":"95.0",...}
где yNNNNNN — значение за год (код года), СКО = id 264023

## Что нужно для полной интеграции
- p_dicIds разный для каждого показателя (узнавать через DevTools или их API структуры)
- для районов СКО: p_parent_id=264023
- переписать dag_extract_taldau.py с GET GetIndexData на POST GetIndexTreeData

## Районная детализация (split_by_kato) — ВАЖНО
Проверено 2026-07-10: показатель "уровень занятости" (702841) в дереве Талдау
РАСКРЫВАЕТСЯ на районы СКО, НО значения по районам пустые (—). Занятость
публикуется только на уровне области. Это ограничение источника, не кода.
Вывод: split_by_kato работает только для показателей, у которых реально есть
данные по районам. Для областных показателей районный запрос вернёт пусто
(обрабатывается как [ПУСТО] и пропускается). Надо проверять детализацию
по каждому показателю отдельно.
