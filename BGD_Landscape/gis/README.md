# Информационная система управления геоданными и ландшафтного планирования

Серверный программный комплекс для ведения базы геоданных, обмена пространственными данными и выполнения ландшафтных расчётов в составе системы поддержки принятия решений.

Авторы: Елубаев Д.Р., Усалинов Е.Б., Телеубай Ж.  
Год создания: 2026.

## Функциональные возможности

- Приём и проверка векторных и растровых файлов, регистрация метаданных и геометрий.
- Ведение иерархических тематических категорий и групп наборов данных.
- Поиск, фильтрация и получение данных с учётом временных периодов.
- Сопоставление атрибутов с кодами КАТО и преобразование показателей по годам в структурированные наблюдения.
- Выдача исходных файлов, GeoJSON, растров Cloud Optimized GeoTIFF и стилей SLD.
- Фоновая обработка заданий и отслеживание статусов выполнения.
- Расчёт экологической ценности, уязвимости, экологических ограничений и отраслевых конфликтов.
- Формирование консервативного, сбалансированного и ориентированного на развитие сценариев функционального зонирования.
- Регистрация результатов расчётов в общем каталоге БГД.

## Архитектура

HTTP API принимает запросы внешних систем и обеспечивает доступ к каталогу, метаданным, геоданным и расчётам. Метаданные, геометрии, наблюдения и состояния заданий хранятся в PostgreSQL/PostGIS; исходные файлы и подготовленные растровые результаты — в MinIO/S3. Задания передаются через RabbitMQ фоновым обработчикам. Обработка растров и выполнение ландшафтных расчётов используют GDAL.

Приложение собирается в исполняемый файл `gis`. Основные команды: `serve` — запуск HTTP API, `worker` — запуск фоновой обработки, `migrate` — управление миграциями БГД.

## Технические требования

- Go с версией и инструментарием, указанными в `go.mod`.
- PostgreSQL 17 с расширением PostGIS 3.5.
- MinIO либо совместимое с S3 объектное хранилище.
- RabbitMQ.
- GDAL, заголовочные файлы GDAL и компиляторы C/C++ для сборки с `CGO_ENABLED=1`.
- Docker и Docker Compose для контейнерного развёртывания.

Поддерживаемые входные форматы: GeoJSON, GeoPackage, Shapefile в ZIP и GeoTIFF.

## Настройка и запуск

Команды выполняются из каталога `gis`. Сначала создаётся конфигурация приложения:

```sh
cp configs/.env.example .env
```

В `.env` задаются параметры подключения к БГД, объектному хранилищу и RabbitMQ. Для локальной инфраструктуры используются значения портов, согласованные с `deployments/docker-compose.yml`.

```sh
docker compose -f deployments/docker-compose.yml up -d postgres minio rabbitmq
go run ./cmd/gis migrate up
```

API и фоновые обработчики запускаются в отдельных процессах:

```sh
go run ./cmd/gis serve
```

```sh
go run ./cmd/gis worker
```

По умолчанию HTTP API использует порт `8080`. Спецификация доступна по пути `/openapi.yaml`, документация — `/docs`. Служебные маршруты `/healthz` и `/readyz` предназначены для проверки состояния приложения и его зависимостей.

Сборка контейнерного образа:

```sh
docker build -f build/package/Dockerfile -t gis:latest .
```

## Ландшафтные расчёты

Исходные растры регистрируются во входных группах модуля ландшафтного планирования. Расчёт выполняется по графу зависимостей: интегральные оценки экологической ценности и уязвимости, экологические ограничения, отраслевые конфликты и функциональное зонирование. Входные растры одного расчётного узла должны иметь согласованные размеры, систему координат и геопривязку.

Управление осуществляется через маршруты `/landscape/slots`, `/landscape/runs` и `/landscape/results`. Результаты сохраняются как растровые наборы данных и доступны через общие маршруты каталога.

Параметры `LP_MAX_WORKERS` и `LP_MAX_NODES` ограничивают параллелизм обработки. Размер обрабатываемого окна задаётся параметром `window_size` расчётного запуска.

## Проверка и сборка

```sh
make build
make check
```

`make check` выполняет `go vet` и тесты. Тесты репозиториев PostgreSQL используют переменную `TEST_DB_URL`, указывающую на отдельную тестовую БГД с применёнными миграциями.

Полное описание методов, параметров и структур ответов приведено в `api/openapi.yaml`.
