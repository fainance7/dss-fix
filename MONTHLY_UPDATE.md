# Ежемесячное обновление данных ETL в DSS

Задача Airflow `dag_monthly_update` запускается 1-го числа каждого месяца в 03:00 по Алматы.

## Что делает

1. **Талдау (БНС).** Запрашивает все активные показатели из таблицы `taldau_indicators_catalog`, по районам и по области, все годы с 2000. Обновляет таблицы ETL `raw_taldau` и `transformed_taldau`. Перед запросом сохраняет копию строк Талдау: если запрос не завершился, таблицы возвращаются к ней, а показатель, который Талдау в этот раз не вернул, остаётся с прежними данными.
2. **Климат (Open-Meteo).** С февраля загружает прошедший полный год, если его ещё нет, и пересчитывает климатические показатели (`dag_build_excel`).
3. **Agromap.** Запускает `dag_sync_agromap`, если он включён в Airflow. Пока он на паузе, шаг пропускается.
4. **Сверка с DSS.** Сравнивает значения ETL со снимком значений DSS. В партию попадают только новые годы в конце рядов, которые уже есть в DSS, и только если:
   - показатель есть в справочнике DSS (название, направление, единица);
   - в последних 5 общих с DSS годах ряда значения ETL совпадают с DSS не меньше чем в 80 % случаев;
   - новое значение отличается от последнего значения ряда в DSS не больше чем в 2,5 раза;
   - значение не было в партии, которую DSS отклонил или удалил.

   Изменившиеся старые значения, пропуски внутри рядов, новые ряды и скачки в DSS не отправляются, а попадают в отчёт на проверку.
5. **Партия для DSS.** Файл `dss_monthly_ГГГГ-ММ.xlsx` в формате загрузки DSS появляется в списке файлов сайта ETL. Если включена отправка, партия уходит в портал приёма данных DSS черновиком. В базу DSS данные попадают только после подтверждения в портале.

## Пересчёт моделей

Пересчёт выполняет сам DSS по своему расписанию (сервис `ai-service`, по Алматы):

- ежедневно в 02:00: прогнозы активных моделей по всем районам;
- по воскресеньям в 03:00: производные показатели из подтверждённых данных;
- по субботам в 04:00: черновые сценарии.

Данные, подтверждённые в DSS, учитываются в ближайший такой запуск.

## Файлы

| Файл | Назначение |
|---|---|
| `airflow/dags/dag_monthly_update.py` | ежемесячная задача |
| `etl/dss_monthly_map.csv` | соответствие названий и единиц ETL и DSS (только пары, у которых значения совпали) |
| `scripts/dss_snapshot.sh` | ночной снимок значений DSS для сверки (только чтение базы DSS) |

Результаты каждого запуска лежат в `artifacts/monthly/`:

- `report_ГГГГ-ММ.json`: сводка;
- `indicators_ГГГГ-ММ.csv`: по каждому показателю, обновляется ли он автоматически, а если нет, то почему;
- `review_ГГГГ-ММ.csv`: значения на проверку человеком;
- `classified_ГГГГ-ММ.csv.gz`: все значения ETL с итогом сверки.

## Установка на сервере

Из папки репозитория на сервере (проект ETL в `/opt/dssetl`):

```bash
sudo install -D -m 755 scripts/dss_snapshot.sh /opt/dssetl/scripts/dss_snapshot.sh
sudo install -d -o "$USER" -m 755 /opt/dssetl/artifacts/dss_snapshot
/opt/dssetl/scripts/dss_snapshot.sh
(crontab -l 2>/dev/null | grep -v dss_snapshot.sh; echo "0 1 * * * /opt/dssetl/scripts/dss_snapshot.sh >> /opt/dssetl/artifacts/dss_snapshot/snapshot.log 2>&1") | crontab -
sudo install -m 644 etl/dss_monthly_map.csv /opt/dssetl/etl/dss_monthly_map.csv
sudo install -m 644 airflow/dags/dag_monthly_update.py /opt/dssetl/airflow/dags/dag_monthly_update.py
docker exec dssetl-airflow-scheduler airflow dags unpause dag_monthly_update
```

Задачи `dag_extract_taldau`, `dag_extract_weather` и `dag_build_excel` должны быть включены (не на паузе). Пользователь, от которого запускается cron, должен входить в группу `docker`.

## Проверка и управление

Команды выполняются через `docker exec dssetl-airflow-scheduler`:

- пробный запуск без запросов к источникам и без отправки: `airflow dags trigger dag_monthly_update --conf '{"fetch": false, "send": false}'`;
- полный пробный запуск без отправки: `airflow dags trigger dag_monthly_update --conf '{"send": false}'`;
- включить отправку черновиков в DSS: `airflow variables set DSS_MONTHLY_SEND true` (выключить: `false`).

Кнопка «Проверить в DSS» на сайте ETL управляется отдельно, настройкой `DSS_DRY_RUN` в `.env`.

Если в ETL показатель назван иначе, чем в DSS, добавьте строку в `etl/dss_monthly_map.csv`. Колонка `factor` переводит единицы, например `0.001` из человек в тыс. человек. Добавляйте строку только после сверки значений ETL и DSS на общих годах.
